## What exists now (state of `test`)

**Apps**
- `backend/`: FastAPI with SQLite. The database is `backend/data_peaks.db` (gitignored). `python -m app.seed` resets the demo.
- `expert-app/`: the expert mobile app (Lovable: TanStack Start, React, Tailwind 4). It calls the backend through the Vite proxy `/api` → `http://localhost:8000`, or `API_PROXY_TARGET`. Screens live in `src/components/datapeaks/PhoneApp.tsx`. Data comes from `useExpert.ts` and `src/lib/api.ts`.
- `frontend/`: the moderator dashboard (Next.js, port 3000). Its pages are `/mod` (alert queue), `/mod/alerts/[id]`, `/mod/questions`, `/mod/leaderboard`, `/mod/panel` and `/mod/risks`. See `frontend/HANDOFF.md`. Moderator requests send `X-Moderator-Key`.
- Run configs are in `.claude/launch.json`: `backend` (8000), `expert-app` (8080), and `expert-app-8001`, which proxies to a backend on 8001.

**How events become alerts and questions today**
1. GreenPT scores ACAPS humanitarian access events (`data/processed/access_events_scored_v7.csv`, 14,847 events). Each event gets intensity × exposure, which gives `impact_score` from 1 to 5. Only 745 events score 4 or more.
2. `scripts/export_api_files.py` matches events to active Risk Radar risks **by country (ISO3) only**. There is no sub-national region: the events file has no admin1 or location column, only free-text `description`. It keeps events from the last 180 days. It writes:
   - `ranked_risks.json`, with priority = 0.4·signal (mean impact of recent events) + 0.3·uncertainty + 0.3·risk impact
   - `alerts.json`, with at most 3 events of `impact_score` ≥ 4 per risk. Each event goes only to its highest-priority risk, and `trigger_id` is always null.
3. `backend/app/seed.py` imports the 22 alerts. It then **writes question Q001 itself**: R1049, using ACAPS trigger T0634's title and description. It also creates invites and 5 synthetic answers. This step is what changes below.
4. When a moderator approves an alert (`POST /alerts/{id}/decision`, with question_text, resolution_criteria and deadline), the backend creates `Q00n`. `route_question` then invites up to 10 experts whose country matches and who have room under `max_open_questions`.

**Where responses are stored**
- They are in the SQLite table `responses` (`backend/app/models.py`). Columns: question_id, expert_id, probability (0–1), reason (≤ 280 chars), round (1 = blind answer, 2 = revision), anonymity_level at the time of answering, and created_at. The `(question_id, expert_id, round)` combination is unique.
- The expert app keeps the expert's own numbers only in sessionStorage, for display.
- Group views never return expert IDs.

**How privacy works today**
- Profile → "Your privacy" saves `anonymity_level` through `PATCH /q/{token}/settings`. The levels are `known_to_acaps`, `pseudonymous` and `anonymous`.
- Every answer stores the level in force at that moment. The moderator view labels each answer with the stricter of the current level and the level at answer time (`services/anonymity.py`). Anonymous answers appear as "Anonymous expert N", and anonymous experts are left off the leaderboard.
- The nickname (`Analyst A`, or `Analyst 3F2A` for experts who joined through an invite) is generated by the server. **The expert cannot change it**: `SettingsUpdate` has no `pseudonym` field.
